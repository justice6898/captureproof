# CaptureProof — submission draft

**Status: local publication candidate; not submitted or published.**

CaptureProof is a focused PayPal integration debugger for independent developers. A checkout can appear successful while provider capture, merchant payment state and delivery disagree. CaptureProof makes those disagreements inspectable and lets a developer compare an integration change against the same declared experiment.

The developer supplies a trusted local CommonJS candidate for the supported, pinned Medusa PayPal integration. CaptureProof freezes its source and runs bounded comparisons covering completed capture, PENDING settlement across restart, an application-discarded response, and unavailable read-back. Deterministic rules compare provider observations with independently committed database state. Missing or unfinished evidence remains INCONCLUSIVE. The interface links each finding to its timeline, source and exact tested comparison.

PayPal supplies the payment semantics, Sandbox API and official server SDK. In the original owned checkout, separately approved USD 12 orders exercised **real PayPal Sandbox** normal capture and recovery after deliberately discarding a successful response. Stored provider reads and local persistence checks confirmed payment and one fulfillment after repeated reads and restart. Separate flawed/corrected Sandbox runs demonstrated the unreconciled-payment mismatch. These were application-layer fault experiments, not verified real network outages.

The central external-integration demonstration is different: **real Medusa 2.7.0, PostgreSQL and PayPal SDK 1.0.0, with simulated PayPal transport**. The upstream integration recorded completed payment while the capture was PENDING. A separately authored repair kept payment unresolved until completed evidence and then persisted one capture row. This does not establish external-plugin behavior against live Sandbox or its fulfillment correctness.

The OpenAI Responses API, using `gpt-6.1-sol` with medium reasoning and default processing in the demonstrated stored response, interprets supplied evidence and source and proposes bounded fixes and regression checks. The current comparison has no matching AI response. A clearly separate earlier analyzed execution is linked from the finding. That exact-run stored response was structurally/factually accepted and its parsed content preservation passed; independent semantic review remains **PARTIAL** because proposed regression coverage was incomplete. The answer is preserved, the repair was authored separately, and nothing is automatically applied. This is not general diagnostic-accuracy validation.

Saved failures can be exported, reduced within explicit execution bounds, replayed and compared with a repair. The selected upstream artifact actually reproduced its failure; its separately identified repair comparison did not reproduce that violation. A self-contained HTML report carries evidence, sources, review and exact downloads for offline inspection. Reduction of a separately labeled injected regression is not evidence of a minimal upstream failure.

The supported execution environment is macOS Apple Silicon, Node 24+, npm and sandbox-exec, using pinned dependencies. Installation and one reproduction succeeded in a separate directory on the same Mac; fresh-machine and independent-user validation remain outstanding. Arbitrary repositories, concurrency guarantees and production certification are outside scope. The working source and setup are prepared for review; repository publication and video delivery remain incomplete; the owner has adopted MIT for original owned material. Fresh-machine and independent-user verification require separate work.
